# Torque AI Memory

A persistent, human- and AI-readable **context and continuity layer** for the
Torque project. It exists so a brand-new Claude Code (or other agent) session can
be pointed at this repository, told "load Torque project memory", and resume
development with full architectural context — without needing the transcript of
any previous chat.

## This is NOT authoritative

**The repository and `Torque_Blueprint_v7_FullSystem.md` are the only sources of
truth.** These files are *derived documentation*: a navigation and reconstruction
aid. Where anything here disagrees with the code, migrations, tests, or the
blueprint, the code/blueprint wins and the memory file is the thing to fix.

Every file here was generated by reading the repository and the blueprint
directly — never by trusting a prior conversation.

## Read order for a new session

1. **`CURRENT_STATE.md`** — one page. Where the project is right now. Read first, every time.
2. **`CONTINUATION_PROTOCOL.md`** — how to actually proceed (the workflow, the rules, the 20 steps).
3. Then, as needed:
   - `PROJECT_CONTEXT.md` — what Torque is and how it is being built
   - `ARCHITECTURE.md` — the current architecture snapshot, every item tagged `IMPLEMENTED` / `PLANNED` / `DEFERRED` / `UNRESOLVED`
   - `DECISIONS.md` — append-only decision log (ADR-style), M1–M6b
   - `MILESTONES.md` — per-milestone history, scope, verification status
   - `INVARIANTS.md` — the catalogue of enforced invariants and where each is enforced
   - `DEFERRED.md` — work that is deliberately NOT built yet (do not implement by accident)
   - `UNRESOLVED.md` — open questions that block or constrain specific future work

## File roles

| File | Nature | Updated |
|---|---|---|
| `CURRENT_STATE.md` | Snapshot, rewritten each milestone | Every milestone |
| `PROJECT_CONTEXT.md` | Slow-changing background | Rarely |
| `ARCHITECTURE.md` | Snapshot + tags, grows | Every milestone |
| `DECISIONS.md` | **Append-only.** History never rewritten. | Every milestone that makes a decision |
| `MILESTONES.md` | **Append-only** per-milestone sections | Every milestone |
| `INVARIANTS.md` | Catalogue, grows | When an invariant is added/changed |
| `DEFERRED.md` | Register, items removed only when actually built | Every milestone |
| `UNRESOLVED.md` | Register, items move to resolved when answered | When a question is opened/closed |

See `CONTINUATION_PROTOCOL.md` → "Memory Update Protocol" for the exact rules on
how to append (and why you must never rewrite decision or milestone history).
